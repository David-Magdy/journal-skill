# HTTP/1.1 Connection Limits and Reverse Proxy Buffering in Server-Sent Events

## Conceptual Core
Browsers enforce a strict ceiling of 6 concurrent TCP connections per origin under HTTP/1.1. Persistent Server-Sent Events (SSE) connections hold a dedicated socket open indefinitely per client tab; opening $\ge 6$ tabs starves the origin pool, causing subsequent API calls and static assets to queue permanently. Migrating to HTTP/2 eliminates this bottleneck by multiplexing concurrent data streams across a single persistent TCP connection.

## Bug / Edge Case Encountered
Users experienced frozen application tabs when opening multiple dashboards. Additionally, real-time metrics were delivered in delayed 30-second bursts because intermediate Nginx reverse proxies buffered upstream streaming response chunks until filling default 4KB memory buffers.

## Key CLI Commands & Environment Tricks
- Disable reverse-proxy buffering dynamically via HTTP headers:
  ```http
  X-Accel-Buffering: no
  Cache-Control: no-cache
  ```
- Nginx configuration for immediate streaming flushes:
  ```nginx
  proxy_buffering off;
  proxy_set_header Connection '';
  proxy_http_version 1.1;
  ```
