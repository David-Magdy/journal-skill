# Path MTU Blackholes and TCP MSS Clamping over VPN Encapsulation Tunnels

## Conceptual Core
Encapsulation protocols such as WireGuard, GRE, and VXLAN add 60–80 bytes of outer header overhead. When traversing an outer network with a standard 1500-byte MTU, inner packets exceeding the reduced tunnel MTU must fragment. If intermediate cloud gateways or firewalls filter ICMP Type 3 Code 4 ("Fragmentation Needed") messages, Path MTU Discovery (PMTUD) fails silently. Small packets (ping, SSH keystrokes) pass effortlessly, but bulk TCP streams stall in a PMTU blackhole.

## Bug / Edge Case Encountered
File transfers stalled immediately following TLS handshakes over a WireGuard tunnel. Senders emitted 1500-byte frames with the Don't Fragment (DF) bit enabled; intermediate nodes dropped the oversized frames, while firewall policies prevented the required ICMP notification from reaching the sender.

## Key CLI Commands & Environment Tricks
- Identify path MTU boundaries using unfragmented ICMP sweeps:
  ```bash
  ping -M do -s 1420 -c 2 <target-host>
  ```
- Rewrite TCP MSS during connection handshakes at the gateway:
  ```bash
  iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
  ```
