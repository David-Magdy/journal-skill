# Preventing Asyncio Event Loop Freezes from Synchronous C-Extensions and CPU Work

## Conceptual Core
Python's `asyncio` runs cooperatively on a single OS thread. An `async def` coroutine only yields control back to the event loop at explicit `await` expressions. Executing CPU-bound computational routines (such as cryptographic signing, compression, or hashing) or invoking blocking synchronous C library functions (such as POSIX `getaddrinfo` DNS resolution) monopolizes the OS thread, pausing all concurrent tasks, heartbeats, and network I/O.

## Bug / Edge Case Encountered
An asynchronous service dropped WebSocket heartbeats and returned 504 gateway timeouts under moderate traffic. Enabling asyncio debug mode revealed coroutines stalling the event loop for 1.48 seconds due to synchronous crypto signing executed directly inside request handlers.

## Key CLI Commands & Environment Tricks
- Detect slow coroutines and blocking callbacks using runtime debug flags:
  ```bash
  PYTHONASYNCIODEBUG=1 uvicorn main:app
  ```
- Offload blocking operations to the default thread pool executor:
  ```python
  result = await asyncio.to_thread(cpu_or_blocking_func, *args)
  ```
