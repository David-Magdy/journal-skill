# Diagnosing File Descriptor Leaks and Socket Hangs via Procfs

## Conceptual Core
Running `lsof` traverses all mounted virtual and network filesystems (including NFS and FUSE), causing diagnostic tools to hang if any mount is degraded. Querying `/proc/<pid>/fd` bypasses external storage entirely by reading the process file table directly from Linux kernel memory. Massive socket counts in `CLOSE_WAIT` indicate an application defect: the remote peer initiated connection teardown (kernel sent ACK), but user code never invoked `close()`.

## Bug / Edge Case Encountered
A service exhausted its 65,536 descriptor ceiling (`EMFILE`). While `lsof` stalled on a stale NFS mount, listing `/proc/<pid>/fd` immediately revealed thousands of unclosed socket inodes stuck in `CLOSE_WAIT` due to unhandled exceptions in client response body readers.

## Key CLI Commands & Environment Tricks
- Count open descriptors without filesystem hangs:
  ```bash
  ls -1 /proc/<pid>/fd | wc -l
  ```
- Inspect socket connection states and TCP buffers:
  ```bash
  ss -tan state close-wait
  ```
- Filter active network sockets by PID:
  ```bash
  ss -tipn 'sport = :8080'
  ```
