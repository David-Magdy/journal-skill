# ELF Position-Independent Code (PIC) Gotchas in CMake Transitive Dependencies

## Conceptual Core
On x86_64 architectures, code packaged into shared objects (`.so`) must be position-independent so the dynamic linker (`ld.so`) can map pages into arbitrary virtual memory spaces. Static archives compiled without `-fPIC` emit 32-bit PC-relative relocations (`R_X86_64_PC32`). When linked transitively into a dynamic shared library, the linker aborts because 32-bit offsets cannot guarantee reach across 64-bit address spaces.

## Bug / Edge Case Encountered
Appending `-fPIC` to global `CMAKE_CXX_FLAGS` failed to propagate to static submodule libraries whose targets managed their own compile option properties. Modern CMake requires setting the target property `POSITION_INDEPENDENT_CODE ON` or setting `set(CMAKE_POSITION_INDEPENDENT_CODE ON)` before declaring static targets.

## Key CLI Commands & Environment Tricks
- Inspect object file relocations for missing PIC compatibility:
  ```bash
  readelf -r static_obj.o | grep -E 'R_X86_64_32|R_X86_64_PC32'
  ```
- Enforce PIC transitively across all CMake targets:
  ```cmake
  set(CMAKE_POSITION_INDEPENDENT_CODE ON)
  ```
