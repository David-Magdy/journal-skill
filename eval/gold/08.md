# CUDA Graph Stream Capture Invariants: Eliminating Host Sync and Allocator Churn

## Conceptual Core
CUDA Graphs eliminate host CPU kernel launch overhead by pre-recording GPU execution into a static DAG. Because stream capture commits to fixed device memory addresses and asynchronous kernel sequences, the CUDA driver disallows any operation that triggers CPU-GPU synchronization, dynamic CPU branching conditioned on device state, or dynamic memory allocations (`cudaMalloc`) during capture.

## Bug / Edge Case Encountered
An attention module evaluated `.item()` on a boolean reduction (`key_padding_mask.any().item()`) to conditionally bypass masked fill operations. This triggered an implicit synchronous device-to-host transfer, crashing the stream capture with `operation not permitted when stream is capturing`.

## Key CLI Commands & Environment Tricks
- Force synchronous execution to isolate host-device transfer calls:
  ```bash
  CUDA_LAUNCH_BLOCKING=1 python infer.py
  ```
- Share static allocator pools across warmup and capture streams:
  ```python
  mempool = torch.cuda.graphs.graph_pool_handle()
  with torch.cuda.graph(g, pool=mempool):
      out = model(static_in)
  ```
